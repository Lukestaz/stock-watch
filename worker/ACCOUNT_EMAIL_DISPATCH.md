# Friends email dispatcher: disabled candidate in PR #4

This batch implements delivery rather than another event-only scaffold: atomic private queue claims, final eligibility rechecks, fixed price-alert formatting, purpose-isolated SMTP, shared candidate sending limits and recorded outcomes. All factories default off. No production runtime, frontend, market fetcher or schedule is wired, no migration/credential changes are performed, and no real email is sent. Migration 0010 is unapplied. Consent session/UI integration and production activation are still unfinished.

Claims have a 120-second lease and unique ownership token. An expired lease before handoff can be recovered; the old worker cannot authorize a send. Immediately before provider invocation, start() rechecks current target/value/revision, account email consent and consent revision, destination verification/revision/provider/binding and observation age (15 minutes to two hours). It commits a one-use dispatch token and attempt count before returning the bound recipient/event payload. Concurrent workers cannot authorize that same row twice.

Opt-out or destination changes before this handoff block sending. A database transaction cannot recall an email after provider handoff begins; this is not a guarantee of cancellation during an already in-flight SMTP exchange or exactly-once delivery. A crash/timeout after handoff may leave delivery uncertain, even if no bytes were ultimately sent. Expired post-handoff leases become outcome_unknown and are not automatically retried. Accepted rows are terminal. Explicit not_sent can retry up to three attempts; failed/unknown outcomes are terminal. Record failures after provider acceptance preserve started-claim state so recovery cannot silently resend.

Quota denial defers the claimed item for 60 seconds without consuming a send attempt, allowing other eligible accounts to proceed. Slot reservations remain charged on failure or changed eligibility. Dispatcher batches default to 10, maximum 25, and return aggregate counts only, never recipients or tokens. The failed counter counts known non-accepted attempts, not necessarily terminal failed rows. Outbox payloads are trusted private server data and must never be exposed through a public endpoint or logs.

Verification and price alerts share global candidate-mail reservation counts (defaults 50 per fixed UTC day and 5 per fixed UTC minute), while personal/destination quotas and cooldowns are purpose-specific. Price-alert defaults are 10 per account and destination per UTC day with a 30-second cooldown; verification retains its existing defaults. Operators must configure consistent global thresholds across purposes. Legacy GitHub Actions mail and unrelated Gmail usage remain outside these counters, so this is not a provider-wide quota guarantee. Existing retention handles both purposes; event/outbox-history retention still needs policy.

The SMTP factory now has a trusted purpose selector, default verification. Price-alert mode permits only the fixed [Stock Watch] Price alert subject; verification mode keeps its fixed verification subject. Caller-supplied arbitrary hosts/senders/subjects remain unsupported. The friends factory binds recipients only from the final outbox lookup, with no global-recipient fallback. Price text uses observed low, target, UTC timestamp and delayed/non-executable-data warnings. Values below 1e-8 USD are rejected rather than formatted as zero.

Seventeen local tests passed using real new SQL on targeted SQLite schemas, seeded account-bound queued events and fake provider callbacks/sockets. They cover two recipients, SMTP wire composition, duplicate/concurrent workers, final opt-out/destination/consent checks, leases, quota fairness, bounded pre-send retries, unknown outcomes and failed outcome persistence. They do not exercise the producer-to-dispatch transition in a single test, actual Cloudflare D1/runtime/TLS or Gmail delivery. CI applies the full repository migration chain and runs producer/verification regressions alongside this suite. New CI must pass; prior PR #4 checks were green before this patch.

Remaining release work: real-session consent composition and usable consent UI, trusted chronological market input and scheduled handler wiring, a full two-account verification/consent/evaluation/dispatch integration test, Worker/TLS checks, secure credential provisioning, migrations and reviewed deployment/live tests. The PR remains draft. WhatsApp account alerting stays off.
